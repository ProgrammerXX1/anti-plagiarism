🛡️ О сервисе detect_norm

Высокопроизводительный микросервис обнаружения мошенничества в документах, реализованный на C++17. Сервис анализирует загруженные файлы и выявляет три категории подозрительных элементов, которые часто используются для обмана систем проверки на плагиат.

Engine: C++17 · ICU (Unicode) · libzip · pugixml · cpp-httplib
Порт: 8001 · API: REST JSON · Swagger: /docs
Форматы: DOCX, DOC, PPTX, ODT, RTF, TXT, PDF · Лимит: 50 МБ на файл

📊 Три категории обнаружения (fraud_type)

Находки всегда возвращаются в строгом порядке: change_word → spaces → hidden_symbols

fraud_typeОписаниеЧто ищемПример
change_word Подмена символов (гомоглифы) В слове смешаны символы из разных Unicode-скриптов (кириллица + латиница). Определяется доминирующий скрипт слова, чужие символы помечаются. информaтике — латинская «a» в кириллическом слове
spaces Аномальные пробелы 1) 2+ обычных пробелов подряд
2) Unicode-пробелы (NBSP, EM SPACE, EN SPACE, THIN SPACE и др.)
3) Невидимые символы (ZWSP, ZWJ, ZWNJ, BOM и др.)		 слово    слово — 4 пробела вместо 1
[invisible] — zero-width символ
hidden_symbols Скрытый текст 1) Почти белый цвет текста (RGB > 240,240,240)
2) Цвет текста ≈ цвет фона (расстояние < 30)
3) Микро-шрифт (< 2pt)		 Текст цветом rgb(250,251,252) на белом фоне — не виден при чтении

🏗️ Архитектура и многопоточность

Сервис использует cpp-httplib ThreadPool для обработки HTTP-запросов. Каждый запрос выполняется в отдельном потоке из пула. Ниже — подробный аудит всех компонентов.

⚙️ Модель потоков ✓ Thread-safe
  • ThreadPool: 2 потока (соответствует Docker cpus=2), макс. очередь 32 запроса
  • Каждый HTTP-обработчик выполняется в отдельном потоке из пула
  • При переполнении очереди (>32) новые подключения ожидают — защита от OOM
  • Конфигурация: svr.new_task_queue = [] { return new ThreadPool(2, 32); }
🔍 Детекторы ✓ Полностью потокобезопасны
  • symbol_substitution.cpp — все статические массивы cyr_homos[], lat_homos[] объявлены как const. ICU-функция uscript_getScript() thread-safe для чтения. Результат — новый вектор на стеке
  • spacing_detector.cpp — только helper-функции с const switch-блоками. detect_spaces() возвращает новый вектор, нет разделяемого состояния
  • hidden_text_detector.cpp — все пороги static constexpr. detect_hidden() создаёт новый вектор на стеке
📄 Парсеры ✓ Полностью потокобезопасны
  • txt_parser.cpp — чистая функция, возвращает новый ParsedDocument. Используется для TXT, RTF, PDF
  • docx_parser.cpp — ZIP + XML (pugixml). Извлекает word/document.xml, парсит runs с цветом/шрифтом/фоном. Для DOCX и DOC
  • pptx_parser.cpp — ZIP + XML. Извлекает ppt/slides/slide*.xml, парсит текст/цвет/размер из <a:r>
  • odt_parser.cpp — ZIP + XML. Извлекает content.xml, парсит стили из office:automatic-styles
  • zip_xml_util.cpp — все zip-дескрипторы локальные, нет глобального состояния
💾 Данные и модели ✓ Потокобезопасны
  • VERSION, PORT, SUPPORTED_EXTS — static const (инициализируются до запуска потоков)
  • tests_dir, static_dir — захвачены по ссылке в лямбдах, но только для чтения после инициализации
  • run_detection() — всё на стеке, нет побочных эффектов
  • DetectionReport, Finding — чистые структуры данных, сериализация без состояния

🛡️ Отказоустойчивость (Fault Tolerance)

Все меры защиты, реализованные для продакшн-эксплуатации:

⏱️ Таймауты ✔ Настроено
  • set_read_timeout(30) — медленный клиент не блокирует поток дольше 30 сек на чтении
  • set_write_timeout(30) — защита от зависания при записи ответа
  • set_idle_interval(5) — проверка keep-alive соединений каждые 5 сек
🚨 Обработка исключений ✔ Настроено
  • Global exception handler — svr.set_exception_handler() ловит любое необработанное исключение, возвращает {"detail": "..."} с кодом 500
  • try-catch в POST-обработчиках — все /detect, /detect/symbols, /detect/spaces, /detect/hidden, /tests/run/{file} обёрнуты в try-catch → 422 + JSON при ошибке парсинга
  • Битый ZIP/DOCX, corrupted XML, bad_alloc — всё корректно возвращает JSON-ошибку вместо краша
🔒 Безопасность ✔ Настроено
  • Path traversal защита — is_safe_filename() блокирует: .., /, \, скрытые файлы (начинающиеся с .)
  • Эндпоинты /tests/run/{file} и /tests/file/{file} валидируют имя файла перед обращением к диску
  • Payload limit: set_payload_max_length(50 MB) — защита от гигантских загрузок
  • CORS: заголовки Access-Control-Allow-Origin для всех ответов
🔄 Перезапуск ✔ Настроено
  • Docker Compose: restart: unless-stopped — автоматический перезапуск при крашах
  • Health-check через GET /health — мониторинг доступности

Ограничения по детекторам

  • change_word работает только для кириллица ↔ латиница. Языки: русский, английский, казахский, турецкий
  • Определяется доминирующий скрипт слова (по количеству букв). Однобуквенные слова пропускаются
  • spaces: одиночный обычный пробел не является находкой — только 2+ подряд или специальные Unicode-пробелы
  • hidden_symbols определяется только в форматах со стилями (.docx, .pptx, .odt). Для .txt, .rtf, .pdf нет информации о цвете/шрифте

Ограничения по форматам

  • .pdf — извлекается текстовый слой через poppler-cpp. Без OCR — сканированные страницы пропускаются. Нет данных о стилях (hidden_symbols не работает). Для полного анализа рекомендуется .docx
  • .doc — старый бинарный формат Word. Обработка как DOCX (ограниченная совместимость)
  • .docx — парсится word/document.xml. Текст в колонтитулах (headers/footers) и текстовых блоках (text boxes) не анализируется
  • .pptx — парсятся все слайды ppt/slides/slide*.xml. Заметки докладчика и мастер-слайды не анализируются
  • .odt — парсится content.xml. Стили из office:automatic-styles (цвет, размер, фон)
  • Offset считается в байтах от начала текстового run (UTF-8: кириллица = 2 байта/символ)
